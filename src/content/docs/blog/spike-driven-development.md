_"Spike-driven development"_ is a term I'm using for a sort of exploratory development with coding agents. It's most useful when I'm working with a new technology/framework/technique/etc. that I'm not very familiar with. In such cases, it's not very useful to try to develop a comprehensive spec and then hand off to a coding agent. The spec would be useless, because I don't know what all decisions will come up or even how to best approach them. I'm at the entrance of a dark cave, with no map.

## Exploration

- discussion
- new spike branch
- following existing patterns/examples in the codebase
- test/revise cycle

## Wrapping Up

- throw it away and start fresh - code is cheap - you have a map of the cave now
- small changes - clean it up and ship it
- large changes - split it up into a series of merge/pull requests, review one by one
